# Sesión 2 de Ako — resumen técnico

30 de septiembre de 2026, 11:16 – ~13:35. Objetivo cumplido: la capa de datos del nivel 1 compila y la precarga se ve en el Database Inspector. Commits `805593a`, `d23b193` (código) y `01293fe` (ficha).

## 1. Repaso de la S1

- **Gradle**: sistema de construcción. Resuelve y descarga las dependencias, compila Kotlin y los recursos, ejecuta KSP (el generador de código de Room) y empaqueta el APK. `app/build.gradle.kts` declara el módulo (`minSdk`, dependencias).
- **Catálogo de versiones** (`gradle/libs.versions.toml`): `[versions]` + `[libraries]` + `[plugins]`. Centraliza las coordenadas y versiones de las dependencias (p. ej. `room = "2.8.5"`); los `build.gradle.kts` las citan como `libs.androidx.room.runtime`. No contiene la versión de la app.
- **`minSdk 26`**: `PBKDF2WithHmacSHA256` está disponible en la API 26 sin librerías externas; cobertura ~98,4 %.

## 2. Conceptos de base de datos relacional

Tabla, fila, clave primaria (PK), clave foránea (FK), `onDelete = RESTRICT` (impide borrar la fila padre referenciada) frente a `CASCADE` (borra las hijas), índice único e `@Entity` de Room (anotación procesada por KSP que genera el esquema SQLite).

## 4. Lo construido

**Paquetes**: `datos/{entidades,dao,repositorios}`, `dominio/modelos`, `seguridad`, `ui`. `dominio` es Kotlin puro (sin `android.*`), testeable con JUnit en la JVM.

**`EstadoComanda`** (`PENDIENTE`, `PAGADA`, `ANULADA`): enum para que el compilador detecte valores inválidos.

**Entidades** (columnas en `snake_case` con `@ColumnInfo`, PK `Long` autogenerada):

| Tabla | Campos | Restricciones |
|---|---|---|
| `categoria` | id, nombre, imagen?, orden, activo, es_por_defecto | índice único `nombre` |
| `producto` | id, categoria_id, numero, nombre, descripcion?, precio_centimos, imagen?, activo | índice único `numero`; FK → categoria RESTRICT; índice `categoria_id` |
| `alergeno` | id, nombre | — |
| `producto_alergeno` | producto_id, alergeno_id | **PK compuesta**; 2 FK RESTRICT; índice `alergeno_id` |
| `mesa` | id, numero | índice único `numero` |
| `comanda` | id, mesa_id, estado, fecha_creacion, fecha_cierre? | FK → mesa RESTRICT; índice `mesa_id` |
| `linea_comanda` | id, comanda_id, producto_id, cantidad, precio_unitario_centimos, nombre_producto | 2 FK RESTRICT; índices |

Los índices sobre columnas FK los añadió Claude porque, sin ellos, Room avisa (evitan recorrer la tabla entera). Principios aplicados: importes en `Int` de céntimos (sin error de coma flotante); lo calculable no se guarda (ocupación de la mesa R3, total R10); la línea congela nombre y precio (R14); las fechas son epoch en milisegundos (`Long`).

**`AppDatabase`**: `@Database(entities = [7], version = 1, exportSchema = false)`, clase abstracta cuya implementación (`AppDatabase_Impl`) genera KSP. Expone 4 DAOs.

**DAOs** (solo lo que usa la precarga; la S3 añade las consultas): `CategoriaDao.insertar(): Long`, `ProductoDao.insertar(): Long`, `MesaDao.insertarTodas(List)`, `PrecargadosDao.insertarAlergenos(List)`. Todos `suspend`: Room prohíbe acceder a la BD desde el hilo principal.

**`EntradaAko : Application`** (registrada con `android:name=".EntradaAko"` en el manifiesto): guarda la única instancia con `by lazy`, que por defecto es `SYNCHRONIZED` (thread-safe). Su `onCreate` lanza `CoroutineScope(Dispatchers.IO).launch { db.openHelper.writableDatabase }`.

**`strings.xml`**: 14 alérgenos (`alergeno_01_gluten` … `alergeno_14_moluscos`, en el orden del anexo II del Reglamento UE 1169/2011), `precarga_categoria_por_defecto`, `precarga_categoria_ejemplo` y `precarga_plato_ejemplo` (RNF-19: nada de textos escritos en el código).

**`Precarga : RoomDatabase.Callback`** (P16): `onCreate` («se llama cuando la base de datos se crea por primera vez») lanza una corrutina en `Dispatchers.IO` que llama a `suspend fun cargar(db: AppDatabase)`. `cargar` inserta, en orden: Otros (`esPorDefecto = true`, `orden = 0`, P44), las mesas 1–60, los 14 alérgenos, y Bebidas (`orden = 1`) con 1 · Agua · 150 céntimos, usando el `id` devuelto por `insertar`. Que `cargar` reciba la BD permite que las pruebas de la S11 la llamen con una base de datos en memoria.

## 6. Problemas y soluciones

1. Paquetes creados fuera de `yunkang.ako` → se rehicieron con clic derecho sobre el paquete correcto.
2. `Comanda.java` con código Kotlin → Android Studio elige el compilador por la extensión; se renombró a `.kt`.
3. Shift + F6 renombró la clase equivocada (`LineaComanda.kt.kt`) → se restauró; el refactor actúa sobre la selección o el cursor.
4. DAOs en `datos/dao/datos/` y `CategoriaDao` en `dao.kt` → se movieron y renombraron; el `package` interno ya era correcto.
