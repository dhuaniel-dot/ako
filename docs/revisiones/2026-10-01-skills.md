### F02 · El hook no escanea archivos nuevos cuando `git add` y `git commit` van en el mismo comando (probado: deja pasar una clave) — **Alta** · mecánico (bloque para Daniel)
- **Dónde:** `.claude/hooks/comprobar-commit.sh:39` (`git diff HEAD`).
- **Qué pasa:** el hook corre **antes** del comando; con `git add -A && git commit -m "S5: …"` los archivos nuevos todavía no están añadidos y `git diff HEAD` no los ve. Prueba del 1 oct en `C:\AKO`: archivo nuevo sin añadir con `AKIA seguida de 16 letras mayúsculas (clave inventada)` → **exit 0 (pasa)**; el mismo archivo ya añadido → exit 2 (bloquea).
- **Arreglo (pegar en el Bloc de notas, `notepad .claude\hooks\comprobar-commit.sh`, sustituyendo las líneas 38-42):**
```bash
claves='sk-ant-[A-Za-z0-9_-]{20,}|sk-[A-Za-z0-9]{32,}|ghp_[A-Za-z0-9]{30,}|github_pat_[A-Za-z0-9_]{30,}|AIza[0-9A-Za-z_-]{35}|AKIA[0-9A-Z]{16}|BEGIN [A-Z ]*PRIVATE KEY'
# Cambios desde el último commit (añadidos o no) + archivos nuevos sin seguimiento (que git add -A subiría)
if { git -C "$raiz" diff HEAD | grep '^+'; git -C "$raiz" ls-files --others --exclude-standard -z | xargs -0 -r grep -hE "$claves" 2>/dev/null; } | grep -qE "$claves"; then
  echo "BLOQUEADO: lo que se va a subir parece llevar una clave de API o una clave privada. Quítala, mete el archivo en .gitignore y avisa a Daniel (skill seguridad)." >&2
  exit 2
fi
```
- **Cómo probarlo:** crear `prueba.txt` con `AKIA seguida de 16 letras mayúsculas (clave inventada)`, sin `git add`, y ejecutar `printf '%s' '{"tool_input":{"command":"git add -A && git commit -m \"S5: x\""}}' | bash .claude/hooks/comprobar-commit.sh; echo $?` → debe decir BLOQUEADO y 2. Borrar `prueba.txt`. Fuente: https://git-scm.com/docs/git-ls-files.
